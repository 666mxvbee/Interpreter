# Compiler

Компилятор на Go.

## Сборка и запуск

    go build -o smcompiler .
    ./smcompiler examples/example.txt 5

Первый аргумент — путь к файлу с программой, дальше через пробел — значения для `read()`.
Результат компиляции сохраняется в `output/<имя файла>.json` (папка создаётся рядом с текущей
директорией). После компиляции программа сразу выполняется на встроенной стековой машине,
и значения `write()` печатаются на stdout — так удобно проверять компилятор.

Тесты: `go test ./...`

## Структура

| Файл          | Что делает                                                                 |
|---------------|----------------------------------------------------------------------------|
| `lexer.go`    | Разбивает текст на токены, пропускает комментарии `-- ...` и `(* ... *)`   |
| `ast.go`      | Узлы дерева: выражения (`Var`, `Const`, `Binop`) и операторы               |
| `parser.go`   | Рекурсивный спуск по грамматике; приоритеты операторов — precedence climbing |
| `compiler.go` | Генерация инструкций SM из AST и печать их в JSON                          |
| `vm.go`       | Интерпретатор SM для запуска скомпилированной программы                    |
| `main.go`     | Разбор аргументов, чтение файла, запись результата                          |

## Как компилируются конструкции

Парсер сводит часть конструкций к более простым узлам:

    x op= e             ==> x = x op e
    { s1 s2 s3 }        ==> seq(s1, seq(s2, s3));   { s } ==> s
    for (i; c; st) s    ==> seq(i, while (c) seq(s, st))
    if (c) s            ==> if (c) s else skip
    elif (c) s ...      ==> вложенный if в ветке else

Генерация кода. Каждый оператор получает метку `next` — куда должно попасть управление
после него — и возвращает флаг `used`: был ли переход на `next`. Метка печатается
вызывающим только при `used = true`. Первой выделяется `L_end_0` для конца программы,
номера идут подряд и расходуются на все метки, включая ненапечатанные.

    read(x)              READ; ST x                                        used = false
    write(e)             <e>; WRITE                                        used = false
    x = e                <e>; ST x                                         used = false
    skip                 ничего                                            used = false
    seq(s1, s2)          <s1 с next=L_seq>; [LABEL L_seq]; <s2 с next>    used = used(s2)
    while (c) s          JMP L_while_cond; LABEL L_while_cody; <s с next=L_while_cond>;
                         LABEL L_while_cond; <c>; JNZ L_while_cody         used = false
    do s while (c)       LABEL L_while_cody; <s с next=L_while_cond>;
                         LABEL L_while_cond; <c>; JNZ L_while_cody         used = false
    if (c) s1 else s2    <c>; JZ L_else; <s1>; JMP next; LABEL L_else; <s2>   used = true
                         (после s2 управление само доходит до next)

Выражения: `LD` для переменных, `CONST` для констант, для `a op b` — код `a`, код `b`, `BINOP op`.

Приоритеты операторов (от слабого к сильному): `!!` < `&&` < сравнения < `+ -` < `* / %`.
Все операторы левоассоциативны. Сравнения и логические операции дают 1 или 0.
